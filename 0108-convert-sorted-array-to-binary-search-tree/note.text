Convert Sorted Array to Binary Search Tree
題目概述：
給一個由小到大排序好的陣列，建一棵高度平衡的 BST（每個節點左右子樹高度差 <= 1）。sorted array 就是 BST 的 inorder，每次選中間當 root 就能保證平衡。

解題邏輯：
用區間遞迴 build(l, r)，負責把 nums[l..r] 建成一棵子樹。

l > r => 空區間，return None。
m = (l + r) // 2，nums[m] 當 root。
左子樹 build(l, m - 1)，右子樹 build(m + 1, r)。
答案是 build(0, len(nums) - 1)。

跟 1008、105 是同一個模板，只差 root 怎麼選：
1008 => preorder[l]，從第一個比 root 大的位置切
105 => preorder 的下一個（p 指標），從 root 在 inorder 的位置切
108 => 區間的中間

踩過的坑：
一開始想不到，想法是「加上子樹後高度合法才加」，但不知道節點怎麼分配。這是先建再檢查（AVL 的做法），很難寫。應該反過來想：一開始就把節點平均分配，構造時就保證平衡，不用檢查。

一開始寫 build(i) 只傳一個 index，沒辦法表示這棵子樹負責哪一段。要改成傳區間 [l, r]。

為什麼選中間就保證平衡：
拿掉中間當 root，剩下的節點平分給左右，最多只差 1 個。
用選中間的方式建樹，高度只跟節點數有關，節點數 +1 時高度最多 +1，所以左右高度最多也只差 1。
每個子樹都遞迴選中間，所以每個節點都平衡。

sorted 這個條件不是多餘的：
平衡來自「選中間」，跟值無關，只看位置。
BST 來自「nums 排序好」，因為建出來的樹 inorder 永遠等於 nums。
如果 nums 沒排序，建出來的樹仍然平衡，但不是 BST，例如 [3, 1, 2] 會讓 3 跑到 1 的左邊。真的遇到沒排序的輸入，要先 sort 再建，總共 O(n log n)。

複雜度：
O(n) time / O(log n) space（遞迴深度 = 樹高，每次從中間切所以是 log n）
