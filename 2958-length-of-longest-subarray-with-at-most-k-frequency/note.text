2958. Length of Longest Subarray With at Most K Frequency

題目概述：
給一個整數陣列 `nums` 和整數 `k`，找最長 contiguous subarray，使得其中每個數字出現次數都不超過 `k`。

解題邏輯：
使用 Variable-Size Sliding Window + HashMap frequency count。

維護：

```text
count[x]
= 目前 window 裡 x 出現幾次
```

每次右指標 `r` 加入新元素：

```text
count[nums[r]] += 1
```

如果：

```text
count[nums[r]] > k
```

代表目前 window 不合法，就持續縮左邊：

```text
count[nums[l]] -= 1
l += 1
```

直到重新合法。

window 合法後：

```text
res = max(res, r - l + 1)
```

為什麼只需要檢查：

```text
count[nums[r]] > k
```

而不是檢查所有元素？

因為在加入 `nums[r]` 之前，上一輪 window 已經保證所有 frequency 都：

```text
<= k
```

這一輪唯一增加 frequency 的元素是：

```text
nums[r]
```

所以唯一可能突然違規的也只有 `nums[r]`。

例如：

```text
k = 2

原本：
[1, 2, 1, 3]

count:
1 -> 2
2 -> 1
3 -> 1
```

加入新的 `1`：

```text
[1, 2, 1, 3, 1]
```

只有：

```text
count[1]: 2 -> 3
```

可能超過 `k`。

所以只需要針對新加入的值判斷。

核心 Pattern：

```text
Longest contiguous subarray
+
每個元素最多出現 K 次
```

可以想到：

```text
Sliding Window
+
Frequency Map
```

固定流程：

```text
1. 右邊加入元素
2. 更新 frequency
3. while window invalid:
       移除左邊元素
4. 更新最長 window
```

踩過的坑：
容易以為每輪都要檢查整個 HashMap，看有沒有任何 frequency 超過 `k`。

其實不用，因為上一輪本來就是合法的，而這一輪只有 `nums[r]` 的 frequency 增加。

所以可以只檢查：

```text
count[nums[r]] > k
```

這也是 Sliding Window 常見 invariant：

```text
上一輪合法
+
這一輪只改變一個新加入元素
→ 只需要修復這次造成的違規
```

複雜度：
O(n)
