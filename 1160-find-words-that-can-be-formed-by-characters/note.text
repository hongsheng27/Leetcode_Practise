1160. Find Words That Can Be Formed by Characters

題目概述：

給定 words 和 chars，判斷每個 word 是否能用 chars 提供的字母組成，每個字母不能使用超過提供的次數。回傳所有合法 word 的長度總和，不同 word 可以重複使用 chars。

解題邏輯：

使用 Counter 統計字母出現次數，直接比較需求量與可用量，不需要模擬字母消耗。
1. 在迴圈外建立 available = Counter(chars)，只需要統計一次。
2. 遍歷每個 word，建立 needed = Counter(word)。
3. 設定 isValid = True。
4. 遍歷 needed.items()，檢查每個字母的需求量。
5. 如果 available[char] < freq，代表字母不足，設定 isValid = False 並 break。
6. 如果 isValid，將 len(word) 加入 res。
核心判斷：

if available[char] <freq:
    isValid = False
    break

踩過的坑：

1. 最初寫法太醜、判斷邏輯太繞。

原本每個 word 都重新建立 Counter(chars)，再逐字扣除數量，還需要判斷字母是否存在及扣除後是否小於 0。

雖然正確，但做了太多不必要的模擬。

這題真正要求的只有：每個字母的需求量是否小於或等於可用量。

以後寫 if 前，先思考「達成題目要求需要滿足哪些條件」，再找出最直接的失敗條件，不要一開始就設計複雜的判斷流程。

2. 不需要額外檢查 char 是否存在。

原本：

if char not in available or available[char] < freq:

Counter 對不存在的 Key 會回傳 0，所以只需要：

if available[char] < freq:

同時涵蓋字母不存在與數量不足。

3. 不使用 all() 也可以寫得簡潔。

使用 isValid = True，搭配 for loop 和 break，即可完成相同的檢查。

不用為了縮短程式碼而強迫使用 all()，清楚表達判斷邏輯更重要。

複雜度：

W = words 數量，k = 平均 word 長度，c = chars 長度。

原始版本：O(W × (c + k)) time，因為每個 word 都重新建立 Counter(chars)。

優化版本：O(c + W × k) time，因為 available 只需要建立一次。

Space：O(1)，因為題目只有 26 種小寫英文字母，兩個 Counter 最多各儲存 26 個 Key。

核心觀念：

Validity Checking 題目，先定義合法條件，再用最簡單的 if 判斷是否違反條件。

不要模擬超過題目要求的過程，也要注意能否將不變的計算移到迴圈外
