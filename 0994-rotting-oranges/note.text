Rotting Oranges 

題目概述
--------
grid 中 0=空格 1=新鮮 2=腐爛，每分鐘腐爛橘子會感染四方向相鄰的新鮮橘子，
問幾分鐘後全部腐爛，無法全爛回傳 -1。

關鍵性質：所有腐爛橘子是同時開始擴散的，且要求的是「最後一顆爛掉的時間」。
「同時多點出發 + 最短時間」= 多源 BFS 的標準形狀。


解題邏輯
--------
[主線：多源 BFS]

1. 初始掃描（一個迴圈同時做兩件事）
   遇到 2：q.append((r, c)) 且 visit.add((r, c))
   遇到 1：freshAmount += 1

   播種時就把所有 2 加進 visit，之後守衛只需判 (nr, nc) in visit，
   不用再多一條 grid == 2。

2. 分層 BFS
   while q and freshAmount:
       for _ in range(len(q)):   # 這一層的所有節點
           pop → 檢查四方向 → 合格的感染、記錄、入隊
       minutes += 1

   for _ in range(len(q)) 是分層的核心：先鎖定當前層的數量，
   這一輪只處理這些，新加入的屬於下一層。

3. 回傳 -1 if freshAmount > 0 else minutes


[為什麼 while q and freshAmount 這個條件是最漂亮的寫法]

因為只有「還有新鮮橘子」才會進下一輪，所以每一輪必定是有意義的一分鐘，
minutes += 1 可以無條件放結尾，不需要任何補償。
同時它也是提早結束的優化：最後一顆爛掉就停，不空跑一層。

其他等價寫法（都對，但要多想一下）：
  - count = -1 起始         → 用負值預先扣掉多跑的那一輪
  - count = 0 + 結尾 if q: count += 1  → q 非空代表真的催生了下一層


[DFS 版本（可寫但不推薦，理解取向）]
DFS 對這題是天生不合的，因為 DFS 不保證第一次抵達某格就是最短時間。

若硬要寫：
  - dfs(r, c, t)，對每個 2 呼叫 dfs(r, c, 0)
  - 不能用單純的 visited set，必須用鬆弛（relaxation）：記錄每格目前最早的
    腐爛時間，只有當 t 比已記錄的更小時才更新並繼續往下遞迴
  - 答案是所有格子時間的 max

代價：同一格可能被反覆更新，最壞可到 O((m*n)^2)，
      而且遞迴深度可能到 m*n 有 stack overflow 風險。

判斷準則：
  問「最短時間 / 最少步數」        → BFS
  問「有沒有路徑 / 連通塊 / 全走一遍」→ DFS
這題是前者，所以 BFS 是唯一合理選擇。


踩過的坑
--------
1. deque([r, c]) vs deque([(r, c)])

   deque(...) 會把傳入的可迭代物逐一展開，每個元素各佔一格。
     deque([r, c])   → deque([1, 2])     兩格 int
                        → popleft() 拿到單一 int → 解包時 TypeError
     deque([(r, c)]) → deque([(1, 2)])   一格 tuple  ✓


2. visit = (dr, dc) 是 rebind 不是 mutate

   這行把 visit 這個名字重新綁到 tuple 上，之後 visit 就不是 set 了。
   (nr, nc) in visit 變成拿 tuple 去比對兩個 int，永遠 False
   → 守衛失效 → 無窮迴圈。

   不會噴錯，因為 tuple 也支援 in，最陰險的一種 bug。
   要修改集合內容用 visit.add(...)。


3. 存進 visit / queue 的是 (dr, dc) 而不是 (nr, nc)

   (dr, dc) 是方向向量，只有四種。存錯的話 visit 最多只有 4 筆，
   queue 裡也全是方向向量被當座標 pop 出來 → 同樣無窮迴圈。

   變數命名太像的時候特別容易中，pop 出來的東西 print 一次就現形。


4. count 數的是「格子數」還是「層數」

   單純 while q: pop; count += 1 數的是拜訪過的格子總數，不是分鐘數。
   必須加上 for _ in range(len(q)) 這層迴圈把 BFS 分層，
   count += 1 才代表一分鐘。


5. 多源必須一次全部入隊，不能一個一個跑再取 max

   錯誤寫法：外層雙迴圈找到每個 2 就各跑一次 BFS，res = max(res, bfs(r, c))

   反例 [[2,1,1,1,1,1,2]]（答案 3，錯誤版給 5）：
   先跑的那個 BFS 把中間 5 顆全吃掉回傳 5，
   後跑的因為格子都在 visit 裡了回傳 0，max 取到 5。

   根本原因：獨立跑 = 輪流計時，但題目是同時擴散。
   多源 BFS 的層數本身就已經是最大時間了，外面不需要再 max
   —— 波前只有一個，沒有多個候選可以比。


6. inner function 改外層變數要 nonlocal

   freshAmount -= 1 是「讀 + 寫」，寫的動作讓 Python 判定它是區域變數，
   讀的時候還沒綁定 → UnboundLocalError。

   （同 BST 那題的坑：list.append() 只改物件內容不需要 nonlocal，
     重新賦值才需要。）


7. 邊界情況

   情況                                    應回傳   為什麼容易錯
   ------------------------------------   ------   --------------------------------
   沒有新鮮橘子 [[2]] [[0]]                  0      迴圈沒跑，count 初始值決定成敗
   有新鮮但沒腐爛 [[1]]                     -1      queue 空，靠 freshAmount > 0 擋
   新鮮被空格隔絕                           -1      BFS 正常結束但 freshAmount 沒歸零
     [[2,1,1],[0,1,1],[1,0,1]]


變體 / 優化
-----------
拿掉 visit，直接改 grid：感染時 grid[nr][nc] = 2，守衛判 grid[nr][nc] != 1 即可。
額外空間 O(m*n) → O(1)（queue 不算）。代價是修改輸入資料。

面試時主動講出這個 trade-off 比選哪一邊更重要。


同型題
------
Walls and Gates (LC 286)  幾乎是同一題換皮：多源 BFS、算距離、把結果寫回 grid
01 Matrix (LC 542)        所有 0 當源頭，求每格到最近 0 的距離
Shortest Bridge (LC 934)  DFS 找出第一座島（連通塊）+ BFS 擴散找最短距離，兩種都用上


----------------------------------------
Time:  O(m*n)  每格最多入隊一次
Space: O(m*n)  queue 和 visit 最壞裝下所有格子
