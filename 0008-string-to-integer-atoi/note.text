題目概述：
模擬 C 語言的 atoi，把字串照規則轉成 32-bit 整數：跳過開頭空白、讀一個可選的正負號、一直讀數字直到遇到非數字，超出範圍就夾到 INT_MAX 或 INT_MIN。考的不是演算法，而是把規則照順序做對、不漏邊界。

解題邏輯：
用同一個 index i 從頭往後推進，四個步驟依序做。

第一步跳過開頭空白：s[i] == " " 就 i += 1。
第二步讀正負號：s[i] in "+-" 就記下 sign，i += 1，只讀一次。
第三步讀數字：'0' <= s[i] <= '9' 就繼續，digit = ord(s[i]) - ord('0')，res = res * 10 + digit。
第四步溢位：在乘之前先檢查 res > (INT_MAX - digit) // 10，超過就 return INT_MAX if sign == 1 else INT_MIN。
最後 return sign * res。

踩過的坑：
題目規定不能用內建函式把字串轉成數字，int() 被明確禁止。isdigit() 只回傳 True/False，不算轉換，可以用；但用 '0' <= ch <= '9' 更保險，完全不依賴內建函式。手動轉換用 ord(ch) - ord('0')，因為 '0' 到 '9' 的字元編碼是連續的。自己建 dict 對照表也符合規則。

溢位檢查在負數也適用：迴圈裡的 res 永遠是正數，存的是絕對值，正負號最後才乘。絕對值一旦超過 INT_MAX（會變成 >= 2147483648），正數一定要夾成 INT_MAX，負數一定是 <= INT_MIN，夾成 INT_MIN 也正確。"-2147483648" 剛好等於 INT_MIN，提早 return INT_MIN 也是對的答案，所以正負兩邊只要跟 INT_MAX 比就夠了。

溢位檢查一定要放在 res = res * 10 + digit 之前。門檻 (INT_MAX - digit) // 10 大約是 214748364，代表「乘之前」res 的上限。如果先乘再檢查，等於拿已經大了 10 倍的 res 去比，"214748365"、"1000000000" 這種正常數字都會被誤判成溢位。

複雜度：
O(n) time / O(1) space
