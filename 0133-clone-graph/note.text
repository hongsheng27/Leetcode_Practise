133. Clone Graph

題目概述：

給一個 connected graph 的起始 node，建立一份完全獨立的 deep copy，所有 node 的 val 和 neighbors 關係都要和原 graph 一樣。

解題邏輯：

使用 BFS + HashMap。

HashMap：

oldToNew[oldNode] = clonedNode

同時負責：

1. 記錄 old node 對應哪個 cloned node。
2. 判斷這個 node 是否已經被 discover。

先 clone 起始 node：

oldToNew[node] = Node(node.val)

並把原 node 放進 queue。

BFS 遍歷時，如果第一次遇到 neighbor：

建立它的 clone，
並把原 neighbor 放進 queue。

之後建立 cloned edge：

oldToNew[current].neighbors.append(oldToNew[neighbor])

核心概念：

Clone Graph =
Graph Traversal
+
old node -> new node mapping

oldToNew 同時可以當 mapping 和 visited / discovered。

踩過的坑：

1. Queue 放入的時間點很重要。

第一次 discover neighbor 時，就要立刻：

建立 clone
+
標記已 discover
+
放進 queue

也就是：

if neighbor not in oldToNew:
oldToNew[neighbor] = Node(neighbor.val)
q.append(neighbor)

不能等到 node 被 pop 出 queue 才標記 visited。

否則同一個 node 在 queue 中等待處理時，可能又被其他 node 重複加入 queue，造成重複處理，甚至重複 append cloned neighbors。

所以 BFS 要記：

discover
→ mark
→ enqueue

而不是：

enqueue
→ dequeue
→ 才 mark

2. 不需要額外 visited。

原本可以同時維護：

visited
oldToNew

但其實：

neighbor not in oldToNew

就已經代表這個 node 還沒被 discover。

因此 oldToNew 可以同時當：

visited
+
old -> new mapping

3. Graph 不一定需要 two-pass。

可以先建立所有 cloned nodes，再第二輪連 edges。

但也可以 one-pass。

當需要某個 neighbor clone，而它還不存在時：

先 create clone，
再直接建立 connection。

建立 node 和處理 node 的 neighbors 是兩件不同的事。

一個 node 可以先被 clone，
之後才從 queue pop 出來處理自己的 neighbors。

4. neighbors 可以直接 append。

Node(val) 建立後，neighbors 預設就是空 list。

所以可以直接：

oldToNew[current].neighbors.append(oldToNew[neighbor])

5. Graph traversal 必須避免重複拜訪。

Graph 可能有 cycle，
也可能有多個 node 指向同一個 node。

因此不能像單純 linked list 一樣一路往前走。

要透過 oldToNew 判斷 node 是否已經被 discover。

6. Graph 和 Linked List 的差別不是 one-pass / two-pass。

兩者都可以 one-pass 或 two-pass。

One-pass 的核心都是：

需要 target clone
→ 不存在就先 create
→ 再 connect

複雜度：

O(V + E) time / O(V) space
