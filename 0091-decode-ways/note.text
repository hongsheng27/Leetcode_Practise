Decode Ways

題目概述：
給一個只包含數字的字串，1~26 分別對應 A~Z，求總共有幾種合法 decode 方法。

解題邏輯：
定義：

dp[i] = 前 i 個字元有幾種 decode 方法

Base case：

dp[0] = 1
dp[1] = 1

如果 s[0] == '0'，直接 return 0，因為 0 不能單獨 decode。

對每個位置 i，有兩種可能：

最後 1 個字元自己 decode

如果：

s[i - 1] != '0'

代表最後一碼合法，所以：

dp[i] += dp[i - 1]

意思是：
前 i - 1 個字元原本有幾種解法，每一種都可以在最後接上目前這一碼。

最後 2 個字元一起 decode

如果：

10 <= int(s[i - 2:i]) <= 26

代表最後兩碼可以組成一個合法字母，所以：

dp[i] += dp[i - 2]

意思是：
最後兩碼綁在一起後，前面剩 i - 2 個字元。
前面有幾種解法，就可以各自接上這個雙位數。

例如 2212：

最後 2 自己 decode：

dp[3]

最後 12 一起 decode：

dp[2]

所以：

dp[4] = dp[3] + dp[2]
= 3 + 2
= 5

Rolling DP：
因為 dp[i] 只依賴 dp[i - 1] 和 dp[i - 2]，所以只需要保留兩個 state。

dp[0] = 前前一個答案
dp[1] = 前一個答案

每一輪先：

cur = 0

如果最後一碼合法：

cur += dp[1]

如果最後兩碼合法：

cur += dp[0]

最後更新：

dp[0] = dp[1]
dp[1] = cur

踩過的坑：

dp[0] = 1 代表空 prefix 有一個合法起始方式，不代表空字串是一個字母。
0 不能單獨 decode。
10 和 20 合法，但 30、40 等不合法。
方法數不是 +1，而是加上前面 state 已經累積的方法數。
Rolling DP 更新時不能把舊的 dp[i - 1] 太早覆蓋掉。

複雜度：
Time: O(n)
Space: O(1)

核心記憶：

最後 1 碼合法
→ + dp[i - 1]

最後 2 碼合法
→ + dp[i - 2]

題型：
1D DP / Counting DP / String DP / Rolling DP
